# Журнал выполнения ЛР 11 (Engee)

Среда: Engee 26.8.2-H3, процессор (5 ядер, 16 ГБ), Python 3.11 из `/user/.user_venvs/py3.11`, PyTorch 2.4.1, дата 20.09.2026. Графического ускорителя нет.

## Что запускалось

1. Пробные запуски (`probe_regimes.py`) на девяти режимах данных с 1200, 2500 и 4000 шагами. Цель — подобрать число шагов и радиус охвата. Итог: `coverage` с $k$ = 5 не превышал 0,06 у всех восьми режимов с 1200 шагами, 0,10 при 2500 шагах и 0,46 при 4000; принят $k$ = 20 и 1500 шагов.
2. Полный прогон 30 вариантов (`run_lab.py 11 <набор>`, пять процессов по одному потоку с приоритетом `nice` 15, итог — 175 обучений: пять наборов × 7 режимов × 5 seed). Обучения записываются в файл `store11_c<набор>.jsonl`, повторный запуск пропускает выполненные.
3. Сводка `summarize_lab.py 11` → `results_30_summary.txt`.
4. Демонстрация варианта 1 (`demo_gan.py 11 1`, seed 101, снимки на шагах 100, 300, 700, 1500) → `demo11_fmt.txt`, `demo11_sheet.png`.

## Что пошло не так

- Первый запуск в фоне через цикл Julia был остановлен перезапуском ядра: процессы-потомки завершились. После этого запуск выполняется отдельным Python-процессом `spawn.py` (новая сессия, `nice` 15) и переживает перезапуск ядра.
- Хранилище результатов возобновляемо, поэтому повторный запуск не пересчитывал готовые обучения.
- Время одного обучения — около 200 с (от 171 до 214 с по средним режимов) при пяти параллельных процессах; при иной нагрузке оно будет другим и в оценке качества не участвует.

Значения метрик получены на синтетических сценах 32×32 из `lab07_lib.py`; переносить на естественные изображения нельзя. Числа таблиц в МУ совпадают с `results_30_summary.txt`.
